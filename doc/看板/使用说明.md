# FilmOS 古诗词看板

2026-10-08，意境选句第三版。本地个人使用，读取项目真实资料；不自动调用AI，不代替教材校对，不宣称提示词已稳定。

## 启动

在项目根目录执行（Python 3.13已验证，无需安装依赖）：

```sh
python3 -m app.server
```

在Codex内置浏览器或本机浏览器打开 http://127.0.0.1:8765 。关闭服务后页面不能保存；在终端按Ctrl+C停止。可用 `--port 8767` 更换占用的端口。只监听本机，不用于公网部署。

## 按意境选句（最新）

默认打开“意境选句”：21,615条来源记录已提取为135,918个连续原文片段，35个主题、17种意境、22个共鸣切入点。分类为提案，规则不能判定的主题/意境保持待细分；全量处理不等于全量精读。

先按主题、意境和共鸣筛选，勾选若干句，可跨不同作品；点击“加入一期作品”选择已有一期或新建一期。每句保存自己的来源与原文，按选择顺序成为独立镜头，之后可调顺序。同一首可取多段，同一句可用于多期。选句篮是当前页面的临时选择，加入一期后才持久保存；刷新前请保存。

点击句子能看完整原文、附近上下文与分类依据，也可以改摘句范围。画面元素、片段用途、学段、分类方法放在“更多筛选”。共鸣是内容策划方向，不是平台热度。当前56条收录关系匹配精读提案，其余为规则初分，89,908个片段意境仍待细分。详见[分类覆盖与边界](../项目/01-古诗词意境/选题库/摘句分类/v1/README.md)。

## 原文与制作操作

1. 诗词资料库：读取21,615条记录，小学130、初中125、高中101、课外典籍21,259。高中课标推荐72个单元有独立入口。按作者、原句、学段、来源典籍、体裁搜索，并组合66种场景／意象／时令／情绪字词线索；每页50条，底部翻页。线索是字词命中，展开详情能看依据；不是确定的创作意境。14个既有分类仍是草案。具体教材与古籍边界见[收录总览](../项目/01-古诗词意境/选题库/收录总览.md)。
2. 点击作品，选中原句再点击“填入选中文字”，或手动复制一两句；摘句必须属于对应原文的连续片段，保留标点。加入已有一期或新建一期。不同期可重复使用同一句。
3. 本期策划记录统一意境、画风及交付要求。每句写画面构想；上移、下移调整顺序。暂时不用可“移回候选”，仍保留所有历史，不参加本期交付；可重新选入。
4. “记录生图迭代”保存完整提示词、模型、参数、参考输入、输出与效果。记录可暂时只有提示词。每次追加新版本，不能覆盖旧版本；同一版本补结果也追加一条完整记录。导入输出图片后选择“采用这个版本”。未知费用、seed等不要编造。
5. 图片满意后点“整理Codex协作请求”，复制到当前对话。Codex实际看图，再依据你确定的视频模型写提示词。按钮不会自动调用模型，也不会自动付费生成。图生视频结果以相同方式记录、导入并采用。
6. 每条选入的诗句都有采用视频后，“导出剪辑交付包”生成ZIP：01-原文编号.mp4等有序视频及交付说明。自行发送给剪辑师。配音、BGM与剪辑目前在看板外完成。
7. “完成素材并归档”锁定这一期记录，含候选、历史版本和采用素材；仍可导出。这表示制作素材准备好，不表示已经完成最终剪辑。归档不阻止诗句进入其他作品。

分类/备注点击保存后才写盘，采用、顺序及候选调整即时保存。页面切换会提示放弃尚未保存的输入；冲突报错时先复制未保存内容，再重新载入。正式作品起步为空，不替用户选择首期。图片视频单文件导入上限200MB；更大的文件手动放进本项目资产库，填写相对路径，例如 `资产库/第一期/视频01.mp4`。

## 文件与Codex协作

- 原文与来源继续位于原有选题库；本看板不改写原文或CSV；完整派生目录见[全库索引](../项目/01-古诗词意境/选题库/全库索引.csv)。2条现代教材记录仅目录与短引文，不是全文。
- 主数据：[看板数据.json](../项目/01-古诗词意境/分期/看板数据.json)。`classifications`按原文编号存分类；`episodes`存每期和每句。分类的`review`为`draft`或`confirmed`，助手草案不能自行变成人工确认。
- 14个初始分类来自[分类草案](../项目/01-古诗词意境/选题库/创作分类草案-v0.1.md)，未修改项即时映射；界面保存后的分类以主数据为准，不再手动同步CSV。
- 导入媒体复制到项目 `资产库/看板导入/`，不覆盖已有素材。文件名只用随机ID区分，不计算哈希。
- Codex写入时使用本地`/api/state`的读写协议，或Python `Store.read()` / `Store.save(data, version)`；同样经过旧版本和归档保护。不要直接重写整份JSON绕开验证。服务运行时改原文目录，重启服务才能载入；分类与制作数据点“重新载入资料”即可。
- 冲突检测使用文件修改时间和大小，不是分布式锁。一个用户顺序协作即可，页面和Codex不要同时修改同一条。磁盘直接修改可被刷新发现，但直接写文件者仍需遵守历史保留规则。
- 界面数据并非浏览器缓存；浏览器关闭或换浏览器后仍从JSON恢复。媒体默认被Git忽略，需自行备份整个项目。Git不是媒体备份。

开发代码：[服务](../../app/server.py)、[界面逻辑](../../app/web/app.js)、[样式](../../app/web/style.css)。方案依据见[实施设计](实施设计.md)。

## 验证与限制

```sh
python3 -m unittest discover -s tests -v
node --check app/web/app.js
```

31项自动测试覆盖摘句区间、分句边界、语境纠偏和筛选接口，以及扩展库计数、来源、高中课标72保留、文字线索边界，以及数据对应、原句引用、持久保存、冲突、历史与归档保护、候选排除、媒体边界、HTTP接口及ZIP。浏览器在独立测试目录实际检查筛选、摘句建期、版本保存、重新载入、采用视频、归档与导出。仅使用本地色块视频，不是AIGC作品。

当前尚未做模型连接、自动批量分类、自动VLM分析、生成队列、配音、BGM、剪辑、多人协作或大媒体性能优化。无AI生成效果和省钱比例的实测。浏览器手动文件选择器未作为本轮自动验收入口，导入接口已通过真实文件请求验证。不要把本地服务发布到互联网。

本轮资料来源、取舍与核验：[资料扩充与界面改版](资料扩充与界面改版.md)。原文21,000余条首次加载仍需读取本地JSON；HTTP启用gzip以减少传输，运行无需Swift或联网。教材目录和开放语料并非逐字校定本，正式采用时再核版本。
