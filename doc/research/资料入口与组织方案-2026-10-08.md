# 三条创作线的资料入口与组织方案

核验日期：2026-10-08。后续用户已确定先一后二、第三项目暂存，并将媒体调整为各项目自有资产库。本文保留早期研究记录；当前目录与方法以[新研究](意境短片开源方法与共用库-2026-10-08.md)和[总入口](../README.md)为准。早期方案将三条线分别按项目管理、复用方法放共用库，真实媒体集中到 `doc/assets/`；该集中媒体方案已被替代。当前完成的是资料入口研究与工作目录，不是全量资料库、模型效果验证或付费生成。

## 为什么采用项目加共用库

| 方案 | 优点 | 主要问题 | 选择 |
| --- | --- | --- | --- |
| 三个项目完全独立，各自复制提示词与素材 | 容易理解，设定不会混用 | 同一方法重复维护，改进无法稳定共享 | 不采用完全隔离 |
| 全部按图片、视频、提示词等类型集中 | 文件类型整齐 | 找不到属于哪一期、哪位角色和哪个设定版本，容易误用 | 不作为主要导航 |
| 项目保留决定与记录，共用库存可复用方法，媒体集中归档 | 项目关系清楚，适合 Codex 按需读取，文件可直接迁移 | 需要维护少量相对链接及采用状态 | 当前采用 |

直接使用 Markdown 和 CSV，无新增生产依赖或应用技术栈。原有清空前的网站方案不自动恢复。将来只有明确出现文件检索或多人协作障碍时，再开展技术选型。

## LibTV 与 Codex 协作

[LibTV 官网](https://www.liblib.tv/)展示图像、视频、音频等创作入口；[插件页](https://www.liblib.tv/plugin)直接指向[官方分发仓库](https://github.com/liblib-ai/marketplace)，仓库记录 Codex Plugin、HTTP Remote MCP 和个人 OAuth 接入，插件版本显示为1.0.0。官方接入入口已核实，但本机未安装、授权或试运行，不承诺当前会话已经能调用。

两份官方工作流提供具体参考：

- [生成与归档工作流](https://github.com/liblib-ai/marketplace/blob/main/plugins/libtv/skills/music-driven-product-ad/references/libtv-production.md)：先查实时模型参数，明确参考素材绑定，保留任务信息；等待超时不能自动当成失败后重复提交。
- [场景、人物与视频工作流](https://github.com/liblib-ai/marketplace/blob/main/plugins/libtv/skills/libtv-blender-live-action/references/workflow-spec.md)：先检查场景静帧和人物设定，再进入视频，针对错误发生的阶段修正。

这些文件分别服务广告、Blender等具体范例。借鉴输入、参考与结果的记录方法，不将其具体软件或镜头规则变成我们的强制流程。没有复制、安装或执行第三方代码；安装前仍应检查当时版本、权限与许可。

| 执行方式 | 优点 | 代价与边界 |
| --- | --- | --- |
| Codex 写策划和提示词，用户在 LibTV 手工提交与导出 | 当前即可围绕文件协作，无需接入新工具 | 用户需带回模型、实际输入、输出与费用，容易遗漏字段 |
| 使用官方 Codex 插件执行，再按同一记录格式归档 | 可能减少复制步骤，并保留任务与模型信息 | 需安装和账号授权，真实调用可能消耗积分或上传素材；效果与归档能力尚未实测 |

现阶段建立两种方式都能使用的文件结构，不自建 API 包装。完整逐模型价格表、用户套餐／余额、首尾帧等模式的具体模型支持未核清，不采用宣传“低至”价格作预算。平台自动改写提示词时，能取得就另外记录最终执行文本；取不到时明确不可见，不能把草稿冒充最终执行内容。

## 相似实现与原始研究的启发

[CineCraft](https://github.com/euisuk-chung/cinecraft)将通用方法和单部作品资料分开，以 Markdown 和技能组织提示词流程。仓库本轮显示 MIT 许可、1次提交，不能据此视为维护成熟的产品；这里只借鉴分层方式，没有复制或安装其内容。

[CineCrew 原始论文](https://arxiv.org/abs/2609.07720)讨论剧本与视频生成之间的镜头约束、资产及连续性，并通过有目标的修正改善结果。它支持将镜头目的和实际反馈显式记录的研究方向，不证明本项目已能稳定出片，也不要求我们先建立多智能体系统。

## 当前范围与后续验证

本轮已建立三个项目的入口、共享模板、媒体归档规则与生成记录方式。没有恢复清空前的研究文件，没有建立应用、数据库、自动生成服务或全部作品素材库。
